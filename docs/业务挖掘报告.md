# 业务挖掘报告：后厨出品与前厅协作智能体系统

> 挖掘对象：单店后厨出品与前厅服务的协作全流程
> 目标用户：企业员工（前厅/后厨一线，约 15 人）与管理员
> 方法：现场观察 + 岗位访谈 + 流程回访 + 需求评审问答
> 日期：2026-11

---

## 1. 业务背景

后厨出品与前厅服务的协作质量直接决定顾客体验与运营效率。当前门店协作依赖口头传话、纸质单据与人工记忆，信息在"前厅点单 → 后厨排产 → 传菜上桌"链路中反复落地为人工动作，既慢又容易丢。

本次挖掘覆盖三段链路：

- **下单链路**：前厅点单 → 单据传递 → 后厨接单；
- **出品链路**：排菜 → 制作 → 出餐 → 传菜上桌；
- **异常链路**：催菜、缺料、改派、过敏备注、漏菜追溯。

## 2. 现状痛点

### 痛点一：单据断点
纸质单与系统单并存，**没有统一排序依据**。后厨凭"先到先做"的直觉排菜，前厅被顾客催问时无法回答"这单排第几"，只能跑到档口现场问——高峰期这种查询每小时可达数十次。

### 痛点二：关联断点
套餐拆单后**过敏备注与子订单失联**：过敏信息留在外层单据，拆到不同档口后无人知晓。漏菜可以补救，过敏事故不可逆，这是全链路风险最高的一环。

### 痛点三：口径断点
前厅、后厨、顾客对"完成"的定义各不相同（出锅 / 端出 / 上桌）。后果是：催菜只能反复电话确认；事后复盘时三项口径对不上，**运营指标没法验收**。

### 痛点四：组织与权限落地难
门店存在**复杂的组织层级**（管理员、厨师长、档口、前厅），但现状是口头授权、越权操作无记录：谁批准改派、谁放行特价菜，事后无据可查。

### 痛点五：自动化空间明确但治理缺位
访谈确认业务方**接受自动派单、自动催菜**，但也明确：自动动作一旦出错（错派、漏派、过度催单），目前没有任何回滚与追责机制。自动化是机会，也是最大的治理缺口。

## 3. 根因归纳

五个痛点的共同根因：**协作信息只在人和纸之间流动，没有进入可计算、可追溯的统一事件流**。缺少归一的单据、随单传递的关键属性、统一的完成口径，以及带权限与留痕的操作通道。

## 4. 需求评审确认结论

| 项 | 结论 |
|----|------|
| 业务规模 | 单店，不做多门店/多租户 |
| 用户规模 | 一线员工约 15 人，单机部署即可承载 |
| 系统对接 | 通过 API 与现有系统（收银/库存等）集成，对接方待定 |
| 审批权限 | 组织层级复杂 → 权限模型 = 角色 + 组织树；一期简化，二期工作流引擎 |
| 留痕要求 | 事后可查即可，普通日志表 |
| 智能体边界 | 允许自动派单/自动催菜，但必须配套降级、限流、可回滚、事故责任界定 |
| 交付节奏 | 6 周上线 MVP，聚焦「归一 → 校验 → 排菜」核心闭环 |

**矛盾裁决**：6 周 MVP 与"全自动 + 复杂审批"冲突，裁决为分阶段——一期做「默认建议 + 一键确认」的半自动派单与简化权限；全自动派单与多级审批流转放二期。事故责任界定（操作人、时间、可撤销标记）一期即写入需求。

## 5. 数智化机会点

| 机会点 | 对应痛点 | 实现要点 |
|--------|---------|---------|
| 单据归一：纸质/口述单统一解析入库 | 痛点一 | 自由文本用 LLM 解析（置信度阈值），规则解析兜底 |
| 可解释排菜：统一计分排序（过敏置顶 > 催菜 > 外卖时限 > 等待时长） | 痛点一 | 确定性规则引擎，每条排序输出理由 |
| 关键属性随单传递 + 过敏 BLOCK 拦截 | 痛点二 | 规则引擎硬门槛 + 人工签核放行 |
| 统一事件流与审计留痕 | 痛点三、四 | 事件驱动 + 日志表，口径全链路统一 |
| 自动派单/自动催菜（带治理） | 痛点五 | 一期半自动；二期全自动，配降级、限流、回滚、责任标记 |

## 6. 未决事项

| 事项 | 当前默认假设（可推翻） |
|------|----------------------|
| 档口终端与网络状况（Q3） | 普通浏览器页面；若网络差改离线优先 |
| 实时性要求（Q8） | 看板 2~5 秒延迟可接受（轮询）；催菜需秒级推送则改 WebSocket |
| 部署方案（Q9） | 先云端单机部署；若要求内网私有化需做无状态化设计 |

## 7. 结论

瓶颈不在「看不见」，而在「对不上」。优先解决归一、关联、口径三个断点，以最小闭环覆盖核心流程；自动化在信任建立后分阶段引入，且每一层自动能力都必须带人工确认、降级与追责通道——这是本次挖掘得出的核心设计约束。

## 8. MVP 边界

- **做**：订单归一 → 过敏/校验 → 计分排菜 → 统一口径看板 → 食安签核 → 审计日志 → 半自动派单；
- **不做（进 backlog）**：全自动派单、多级审批工作流、库存联动、外卖平台对接、多门店、移动端档口屏。
